# ネット予約のセットアップ手順

所要時間の目安: **30〜40分**。プログラミングの知識は不要です。

---

## なぜこの構成なのか

このサイトは GitHub Pages で配信している**静的サイト**で、サーバーがありません。
Googleカレンダーの読み書きとメール送信には認証情報が必要ですが、
ブラウザ側のコードに置くと**閲覧者全員に見えてしまいます**。

そこで **Google Apps Script（GAS）** を唯一のサーバーにしました。

| 項目 | 内容 |
|---|---|
| 実行場所 | サロンのGoogleアカウント上（GAS） |
| 費用 | **無料**（Googleアカウントのみ） |
| 認証情報の置き場所 | GASのスクリプトプロパティ（外部から見えません） |
| 予約データ | Googleカレンダー（正）＋ スプレッドシート（変更・キャンセル用の控え） |
| メール送信 | GmailApp（別サービスの契約が不要） |
| 管理画面 | **作りません**。Googleカレンダーとメールだけで運用します |

4. タイムゾーン: **(GMT+09:00) 日本標準時**

**このカレンダーは一般公開しないでください。**
「設定と共有 → 予定のアクセス権限」で「一般公開して誰でも利用できるようにする」の
チェックが**外れている**ことを確認してください。

## 手順5. 公開する

1. 右上「デプロイ」→「新しいデプロイ」
2. 種類の選択（⚙）→ **ウェブアプリ**
3. 設定
   - 説明: `v1`
   - **次のユーザーとして実行: 自分**
   - **アクセスできるユーザー: 全員**
4. 「デプロイ」→ 初回は権限の確認が出ます
   - 「詳細」→「（プロジェクト名）に移動」→「許可」
5. 表示された **ウェブアプリのURL** をコピー

> 「アクセスできるユーザー: 全員」は、サイトの訪問者が予約できるようにするために必要です。
> URLを知られても、**できるのは予約と自分の予約の変更だけ**です。
> 他人の予約は署名付きトークンが無いと参照できません。

### 動作確認

コピーしたURLをブラウザで開いてください。
`{"ok":true,"missing":[]}` と表示されれば設定は完了です。
`missing` に項目名が出た場合は、その設定値が未入力です。

## 手順6. サイト側に接続する

GitHub リポジトリの **Settings → Secrets and variables → Actions → Variables** で追加します。

| 名前 | 値 |
|---|---|
| `NEXT_PUBLIC_BOOKING_API_URL` | 手順5でコピーしたウェブアプリURL |

`.github/workflows/pages.yml` のビルド手順に、この変数を渡す1行を追加してください
（本リポジトリでは追加済みです）。

設定後、GitHub Actions で `pages.yml` を実行するとネット予約が有効になります。
**未設定のあいだは予約フォームを表示せず、案内文に切り替わります**（壊れた画面になりません）。

## 手順7. リマインドメール（任意）

1. Apps Script の左メニュー「⏰ トリガー」→「トリガーを追加」
2. 実行する関数: `sendReminders`

送信タイミングは `Code.gs` の `CONFIG.reminder` で変更できます。

## 設定を変えるとき

| 変えたいこと | 変更する場所 |
|---|---|
| 営業時間・定休日 | `src/data/hours.ts` **と** `Code.gs` の `CONFIG.businessHours`（両方） |
| メニュー・料金・施術時間 | `src/data/booking/menus.ts` **と** `Code.gs` の `MENUS`（両方） |
| 準備・片付け時間、予約間隔、受付期間、当日締切 | `src/data/booking/settings.ts` **と** `Code.gs` の `CONFIG`（両方） |
| 1日の予約上限 | 同上 |

> ⚠️ **必ず両方を同じ値にしてください。**
> ずれると「画面では選べるのに確定できない」状態になります。
> サイト側だけを直しても、サーバー側が拒否します（安全側に倒す設計です）。

## セキュリティで気をつけること

- **Googleアカウントの2段階認証を必ず有効にしてください。** このアカウントが
  予約データと顧客情報のすべてを持っています。
- カレンダーの共有は最小限に（共有しないのが基本です）。
- `BOOKING_TOKEN_SECRET` を変更すると、**発行済みの変更・キャンセルリンクがすべて無効**になります。
- スプレッドシートの共有リンクを作らないでください。
- 予約データの保存期間を決め、古い行は定期的に削除してください（個人情報の保有期間）。

## うまくいかないとき

| 症状 | 原因と対処 |
|---|---|
| 予約ボタンを押しても何も起きない | `NEXT_PUBLIC_BOOKING_API_URL` が未設定。手順6を確認 |
| 「通信に失敗しました」 | GASのデプロイが「全員」になっていない。手順5を確認 |
| 「予約システムに接続できませんでした」 | `CALENDAR_ID` が誤っている |
| 空き時間が出ない | カレンダーに終日予定が入っていないか確認 |
| メールが届かない | 迷惑メールフォルダを確認。GASの実行ログでエラーを確認 |
| コードを直したのに反映されない | **デプロイし直す**必要があります（「デプロイを管理」→ 鉛筆 → バージョン: 新バージョン） |
