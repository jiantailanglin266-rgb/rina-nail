# チャットボットの仕様

## 何をするものか

サイト右下のボタンから開く、**よくあるご質問に自動で答えるチャット**です。
5言語（日本語・英語・簡体字・繁体字・韓国語）すべてで動作します。

## 生成AIを使っていない理由

このサイトは GitHub Pages で配信している**静的サイト**で、サーバーを持っていません。

ChatGPT などのAPIを呼ぶには APIキーが必要ですが、
サーバーが無いとキーをブラウザ側のコードに書くことになり、
**閲覧者全員に見えてしまいます**（第三者に使われ、料金を請求されます）。

そのため、サイト内の情報を知識ベースにした**検索方式**で実装しています。

### この方式の利点

| | 検索方式（採用） | 生成AI方式 |
|---|---|---|
| 費用 | **0円** | 従量課金（質問ごと） |
| 誤情報 | **原理的に起きない**（サイトの文をそのまま返す） | もっともらしい嘘を答えうる |
| 応答速度 | **即時**（通信なし） | 1〜3秒 |
| 表記ゆれ | サイト本文と必ず一致 | ずれる可能性あり |
| 対応できる質問 | 登録した範囲のみ | 広い |
| 個人情報 | **外部に送信しない** | 外部APIへ送信 |

ネイルサロンの問い合わせは「営業時間」「駐車場」「料金」「予約方法」に集中するため、
**誤情報を出さないことのほうが、幅広く答えられることより価値がある**と判断しました。

## 回答の作り方

**すべての回答はサイトの既存データから組み立てています。**
チャット専用の文言は書いていません。

| 質問の種類 | 回答の出どころ |
|---|---|
| 営業時間 | `src/data/hours.ts` |
| 料金 | `src/data/menu.ts` |
| 住所・駐車場 | `src/data/site.ts` ＋ 翻訳ファイル |
| 施術の流れ | `home.flow.steps`（トップページと同じ） |
| その他11問 | よくあるご質問ページ（`faq.groups`） |

つまり **営業時間を変更すれば、本文・構造化データ・チャットが同時に変わります。**
チャットだけ古い情報を答える、という事故が起きません。

## 検索の仕組み

日本語・中国語は単語の間に空白が無いため、
**文字を2つずつ並べた組（バイグラム）** に分解して照合します。
形態素解析の辞書を同梱すると数MB増えて表示が遅くなるため採用していません。

得点は「入力された質問のうち、どれだけをその項目で説明できるか」（0〜1）です。
実装にあたって、次の4つの落とし穴を実際に踏んで対処しました。

1. **項目の語数で割ってはいけない** — キーワードを丁寧に登録した項目ほど不利になり、
   「営業時間は？」が営業時間の項目に当たらなくなりました。
2. **頻出語を重く見てはいけない** — 「を教えて」「ますか」はどの質問文にも出るため、
   「行き方を教えて」が「施術の流れを教えてください」に引っ張られました。
   各語の珍しさ（IDF）で重み付けして解決しています。
3. **知らない語を分母に入れすぎてはいけない** — 言い回しが違うだけで一致率が下がります。
   逆に無視しすぎると「近くのラーメン屋」が「メンズ」に当たります（“メン”が共通）。
   中くらいの重みで折り合いをつけています。
4. **長音符「ー」を記号として消してはいけない** — 「カード」が「カ」「ド」に分かれ、
   支払い方法の質問に当たらなくなりました。

**言い回しだけの一致では回答しません。** 「教えてください」「ありがとう」のような入力には
回答も候補も出しません（`tests/chat.test.ts` で検証しています）。

## 答えられないときの動作

| 状況 | 動作 |
|---|---|
| 確信度が高い（一致率45%以上） | 回答＋関連ページへの導線を表示 |
| 確信度が低い（20〜45%） | 「もしかして」と候補を最大3件表示 |
| 一致しない | よくあるご質問ページへ案内 |

**分からないことを推測で答えることはありません。**

## 質問と回答を追加する

### よくあるご質問を増やす（推奨）

`src/i18n/messages/*.json` の `faq.groups[].items` に追加してください。
`id` を付けると、チャット・FAQページ・FAQPage構造化データの**3か所に同時に反映**されます。

```json
{ "id": "kids", "q": "子連れでも大丈夫ですか？", "a": "事前にご相談ください。" }
```

別の言い方でも拾えるよう、手がかり語を `chat.faqKeywords` に追加します。

```json
"faqKeywords": {
  "kids": ["子連れ", "子ども", "赤ちゃん", "ベビーカー"]
}
```

**5言語すべてに追加してください**（`npm run typecheck` で欠落を検出できます）。

### データから答える項目を増やす

`src/lib/chat/knowledge.ts` の `dataEntries` に追加し、
`chat.intents` に質問文と手がかり語を5言語ぶん足します。

## 将来、生成AIに切り替える場合

**サーバーが必要です。** Vercel などへ移行すれば、次の構成が使えます。

```
ブラウザ → /api/chat（サーバー側でAPIキーを保持）→ Claude API → 回答
```

その際も、**回答の根拠は今の知識ベースをそのまま渡す**構成を推奨します
（いわゆるRAG）。サイトに書いていないことを生成させないためです。
`src/lib/chat/knowledge.ts` の `buildKnowledge()` はそのまま使えます。

移行しても残すべき設計:
- 回答は `src/data/` と翻訳ファイルを唯一の情報源にする
- 料金・電話番号など未確定の値は答えさせない
- 「分からない」と言える動作を必ず残す

## テスト

`tests/chat.test.ts` に42件。実際に入力されそうな27通りの聞き方が
正しい項目に当たるかを、日本語・英語・中国語・韓国語で検証しています。
質問や手がかり語を編集したら、必ず `npm run test` を通してください。
